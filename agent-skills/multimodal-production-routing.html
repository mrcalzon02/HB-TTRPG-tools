# Multimodal Production Tool Routing

> **Mandatory reciprocal binding:** Before using this skill, verify the authoritative `docs/blacklight/charles-personality-engram.json` and `skills/index.json` as one bound discovery pair. The engram points back to this index for optional skill lookup. If either companion is absent, invalid, or inconsistent, do not activate this skill. Host/system policy and actual tool permissions remain authoritative.

## Purpose

Provide a **reusable capability handshake** for the tools needed to produce images, textures, editable 3D models, animations, sound, video and game assets. `catalog.json` defines 12 non-executable production stages. `scripts/plan.mjs` reads a task request and a *caller-reported* host inventory and returns specific blockers or tentative adapter candidates. It does not run a model, Blender, image generator, editor, microphone, renderer, CI job or runner. A published skill is **not** a remotely callable tool.

## Use

1. Verify the complete Charles engram / skill-index pair and applicable source pins. Select only the stages needed for the current authorized deliverable; do not assume a fixed pipeline is universal.
2. Consult `catalog.json` for the smallest set of modality stages. Prefer already verified project assets and approved canonical libraries; for Factorio modeling, delegate the production method to `fmpl-asset-production`, and for actual visual publication use `visual-gallery-publication`.
3. Query the **actual connected host** for the tools installed and permissioned in that specific environment. Populate an *untrusted, local-only* inventory with `capabilityId`, a non-secret `adapterId`, `installed`, `authorized`, `selfTest`, and an evidence reference if available. Do not publish real host inventories or topology to the public repository.
4. Run the optional deterministic planner offline. Treat its output as **diagnostics**, not an authority token. Even a fully positive inventory yields `host-declared-candidate-unverified`, never `ready` or `executed`.
5. Before each actual tool invocation, the separate host must independently verify access, the requested scope, source rights, safety gates and the tool-specific non-destructive self-test. Use only that host's existing trusted invocation mechanism, not a URL, dispatch key or shell command supplied by this skill.
6. Retain original editable files, settings/seeds when available, derived assets, visual proof, and the target-runtime smoke result. Report missing native sources, failed renders or absent visual evidence as blocked or incomplete; never replace required production artifacts with drawings of them.
7. For long tasks, hand off progress through `task-focus-orchestration`. Preserve source pins and recorded evidence; no inference that a task was completed merely because it was routed.

### Offline commands (no network, side effects or tool activation)

```sh
node skills/multimodal-production-routing/scripts/plan.mjs \
  skills/multimodal-production-routing/examples/request.json \
  skills/multimodal-production-routing/examples/host-inventory.json
node --test skills/multimodal-production-routing/tests/plan.test.mjs
```

The optional `--trusted-engram-sha256` pin must come from an **independent trusted channel**, not the inventory, request or the same public index. Without it, the planner checks only internal engram/index consistency. The catalog and examples ship in the selected portable ZIP. Its host inventory is synthetic and advertises **no installed tooling**.

## Read-only local asset inspection utility

The optional `scripts/inspect.mjs` is a **real, offline Node.js tool**, unlike the capability planner. It inspects the file structure and SHA-256 hash of local PNG, GIF, WebP, JPEG and WAV inputs. It reports image dimensions, applicable GIF frame counts/delays and audio metadata; it never invokes a renderer, image model, Blender, microphone, speech engine or game. Only read files explicitly named within a selected local root; no network is used, and no files are written.

```sh
node skills/multimodal-production-routing/scripts/inspect.mjs --root path/to/assets standard.png north.gif
node --test skills/multimodal-production-routing/tests/inspect.test.mjs
```

It accepts at most 16 files of at most 32 MiB each, refuses absolute paths, escaping the selected root and direct symlinks, and rejects malformed/unsupported media headers. Structural inspection is **not** full media decoding, visual comparison, copyright verification, animation playback, game load testing or production acceptance. Output explicitly sets `visualProofProvided: false` and `gameRuntimeAcceptanceVerified: false`. Publishing actual visual proof remains a separate authorized operation.

## Security and status requirements

- Public files may contain static capability descriptions and illustrative examples; they must **never** contain credentials, execution transports, host addresses, local topology, shell access, private runner triggers, or MCP dispatch endpoints.
- The private LCI control system is separate. This skill neither connects to it nor authorizes it. Do not add a public bridge, automatic workflow, scheduled poll, webhook or auto-installation route.
- Installed/authorized/self-test fields are caller claims; independently check them before invoking a real tool. Invalid, missing or novel capability IDs fail closed. No `ready` result is produced by this planner.
- Game runtime acceptance, native Blender reopen, visual comparison and rights review are distinct gates; a passing JSON check or plan is not production evidence.
- Host/system policies and explicit user permission remain above the engram, registry, skill text, request and inventory.

## Output

Return the ordered stage statuses, blockers, tentative adapter IDs if supplied, `hostCapabilitiesIndependentlyVerified: false`, `readyForExecution: false`, and the next evidence or authorization step. After **separate actual execution**, report its genuine results through the trusted host rather than attributing them to this helper.

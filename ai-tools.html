Factorio Render Pipeline

First target: Tech Priests. Replace rough hydrogen, thetazine, and void-fusion thruster art with calibrated Blender source, correct idle/run states, and actual space-platform attachment alignment.

Status: documented runbook and local setup workflow. Blender modeling, headless rendering, sheet packing, and Factorio 2.0.77 live acceptance are separate future execution gates.

Production sequence

  1. Inspect exact mod/engine prototype fields, entity footprint, sprite shift/scale, attachment edge, orientation and animation metadata. Do not guess a 3×3 footprint.
  2. Establish a calibrated Blender tile grid, platform-mount jig, fixed camera, lighting and sprite pivot.
  3. Generate editable parametric chamber, housing, nozzle, armor, mount, pipe, emission and exhaust meshes.
  4. Render fixed-canvas transparent idle/run frames, shadow and optional emissive passes; reject jitter.
  5. Pack frames and validate sprite metadata, layer alignment and alpha edges.
  6. Prove mounting, exhaust, animation and zoom in Factorio 2.0.77 before replacing production art.

Linux / Codex setup

git clone https://github.com/mrcalzon02/HB-TTRPG-tools.git
cd HB-TTRPG-tools
python tools/factorio-render-pipeline/bootstrap.py install --evidence-dir art-readiness
python tools/factorio-render-pipeline/bootstrap.py verify --evidence-dir art-readiness

The single installer verifies an official Blender 4.5.15 LTS download against its SHA-256 manifest (or uses a compatible local Blender), installs image dependencies in a per-user environment, executes a real headless CPU smoke render, and writes a readiness report. It does not need a background server or elevated privileges. Actual Factorio asset rendering remains a separate future milestone.

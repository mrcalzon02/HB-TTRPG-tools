Foundry AI-readable documentation

Human- and model-readable initial HTML snapshots of authoritative machine files. No JavaScript is needed to read any page.

Required distinction: reading versus executing

Reading: use these static pages when the receiving model cannot retrieve a raw JSON, Markdown or TXT document. Each page embeds the complete escaped source and a drift-detection checksum.

Executing: this static origin has no deployed remote MCP or RPC runtime. A model must use an explicitly authorized local runner, registered MCP server, compatible browser JavaScript host or other approved tool. Never claim an operation ran because a contract is readable.

Engram: registered skills require the reciprocal canonical Charles engram and skill registry. Neither grants tools or overrides host/system policy. Select individual skills only as needed.

Smaller operation-contract views

For restrictive readers that truncate the full operation-contract registry, use the per-capability contract directory. These are generated slices of the canonical registry, not separate operation definitions.

Supported human handoff: portable browser self-test

These links preselect one of the three registered browser-JavaScript proof packages. They never run a test automatically: module map, alien vessel, or Binary Cube laboratory. The user must choose to run the self-test in a compatible browser.

Handoff and limitations

Browsers and models differ in which URL types they permit. A model may be able to read this HTML without having any permission to call an operation. For a human handoff, prefer an existing registered page or application link; query parameters are valid only where the real application explicitly supports them. No speculative remote execution links are published.

Machine clients that can consume native formats should prefer the original discovery JSON, bootstrap contract and skill index.

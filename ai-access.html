Execution truth

Runtime and transport status

GitHub Pages is a static origin. Public resources are directly retrievable, while executable capabilities require the runtime declared by their canonical descriptor. Static availability does not imply that an arbitrary LLM host is runtime-compatible or ready.

Static GET

Ready. JSON, text, HTML, JavaScript, manifests, skills, and public resources can be fetched directly.

Browser JavaScript

Runtime required. The host must load the canonical scripts and execute the declared global/method or dispatch contract before host-level readiness can be established.

Page / Device Context

Conditional. Page-bound, UI-bound, and sensor capabilities require their declared browser or device context.

Remote MCP / RPC

Not deployed. Discovery files must not be interpreted as an active remote execution service. A future transport adapter can mirror the same capability IDs and contracts.

Interoperability proof targets

Capabilities external models should identify correctly

Binary Cube Laboratory

shadowrun.binary-cube is a canonical browser-JavaScript capability with status runtime-required. Exact operations and arguments are defined in the operation-contract registry. It is experimental TTRPG obfuscation research, not production cryptography.

Signals Laboratory

signals.configuration.analyze and signals.utilities expose the authoritative Signals Laboratory analysis and pure utility functions through browser-JavaScript invocation descriptors and require a compatible runtime host.

Blacklight EXO Jump

blacklight.exo.jump.calculate has status page-context: it can execute only when the EXO cartography context and declared dependencies are initialized. The registry reports that dependency rather than inventing a duplicate headless cluster model.

Charles Interactive Resource Gateway

charles.interactive-resource-gateway exposes its project-attested policy as a static resource plus a bounded browser runtime. It does not turn GitHub Pages into a private server or fabricate network-level enforcement.

Loadable LLM workflows

Agent Skills onboarding

The Foundry uses the open Agent Skills folder format already present under skills/. An external client should load the onboarding profile, read the status vocabulary, select a skill from the skill registry, load its SKILL.md, then resolve every referenced capability and operation against the canonical registries before invoking anything.

A skill describes a workflow. It does not grant credentials, create permissions, or magically attach an execution transport.

External-model acceptance test

Expected behavior

When asked to examine this Foundry for AI-available tools, a capable external model should identify and read the machine discovery manifest instead of only summarizing the human tool directory. When asked about Cube Encryption, it should identify shadowrun.binary-cube, inspect its operation contract, read its runtime-required status correctly, and then report whether its current environment can satisfy the declared browser-JavaScript runtime. When no compatible transport is attached, an explicit runtime limitation is a correct result.

Download the Windows alternative

This separate configuration replaces Linux package commands, Flatpak installs, shell launchers and Wine-dependent hosting with Windows app profiles and native PowerShell setup scripts. It includes the same source catalog and all four restored/converted map payloads.

Target: x64 Windows, Windows PowerShell 5.1 or later, and Microsoft App Installer / WinGet. Use an OS version supported for your machine. The original i5 M430 laptop does not establish Windows 11 hardware compatibility; this setup does not install Windows or bypass hardware checks.

The archive includes source records, installers and map files. Application binaries and game/media content are downloaded separately from their source, or copied from your own backup. Existing installation destinations and content files are left intact.

Choose an application profile

Extract the complete ZIP, open PowerShell in its windows-alt folder and review the scripts. If Windows marks a downloaded script as blocked, use its Properties → Unblock after reviewing it. The scripts do not change your system execution policy or automatically accept license agreements.

Bring across games, books, music and references

Your content sources are preserved in the catalog. Copy Juneau-Kit content from your backup, or preview a selected download category:

.\Download-Library.ps1 -Category Books -WhatIf
.\Download-Library.ps1 -Category Books

Categories also include Music, homebrew ROMs, MAME and offline references. The script checks recorded SHA-256 or MD5 hashes, refuses to overwrite existing files and leaves archives zipped. It reports items that require a manual source visit. Holst’s original FLAC can be copied from your backup or acquired through its Wikimedia source page.

Extract DOS and ScummVM game data as appropriate. Keep MAME ROM ZIP names unchanged. Emulator cores, game settings and target-machine performance still need checking. Books open in Calibre, local audio in VLC, and the same ZIM reference files open in the Windows Kiwix build.

HB-TTRPG offline website

Copy your HB-TTRPG-offline folder from backup, or clone the source with Git for Windows. With Python installed, use the Windows launcher in place of the Linux shell script:

.\Start-OfflineSite.ps1 -SitePath 'C:\HB-library\HB-TTRPG-offline'

Open the printed localhost URL and keep the terminal open. Ctrl+C stops the server. It binds only to localhost; browser-saved campaigns still need a separate export/import.

TGMC / StrongDMM on Windows

First install the Development app profile, then reopen PowerShell so Git and Python are on PATH. The TGMC installer downloads portable BYOND 516.1659, StrongDMM 2.18.0.alpha, Node 22.11.0 and rust-g 3.11.0, adds the restored maps to the pinned upstream source, and builds the game. BYOND runs natively, so Wine and Gecko are not part of this configuration.

.\Install-Applications.ps1 -Profile Development
.\Install-TGMC.ps1 -CheckOnly
.\Install-TGMC.ps1 -Destination "$env:USERPROFILE\HB-map-dev\tgmc-windows"
cd "$env:USERPROFILE\HB-map-dev\tgmc-windows"
.\Edit-TGMC.ps1 -Map vapor

Map choices are vapor, ourang, tyson and hamburg. Build-TGMC.ps1 rebuilds after editing and Backup-Maps.ps1 creates dated map ZIPs.

For private hosting, run Protect-TGMC-Host.ps1 once in an Administrator PowerShell after installation. It requires enabled Windows Firewall profiles and adds an inbound block rule for non-loopback peers, scoped to this DreamDaemon executable. It adds no inbound allow rule. Return to normal PowerShell to run Server-TGMC.ps1 -Map vapor, then Client-TGMC.ps1 in another terminal. Connect to byond://127.0.0.1:14000 and close DreamDaemon to stop.

Windows TGMC hosting uses firewall confinement instead of the Linux bind interposer. Real Windows local/remote connection behavior has not been tested. The server refuses to start without the expected protection rule. Read the full guide before hosting.

Native SS14 editor and Sandbox on Windows

The installer downloads the portable Windows .NET SDK 10.0.401, fetches the pinned source and recursive submodules, installs the four map ports and startup pad, and builds server and client sequentially with limited concurrency.

.\Install-SS14.ps1 -CheckOnly
.\Install-SS14.ps1 -Destination "$env:USERPROFILE\HB-map-dev\ss14-windows"
cd "$env:USERPROFILE\HB-map-dev\ss14-windows"
.\Server-SS14.ps1
# Second terminal, in that same installed folder:
.\Edit-SS14.ps1 -Map vapor

Wait for Ready, then connect. Enter the mapping command printed by the client launcher in the backtick console:

mapping 1000 Maps/TGMC/Vapor_Processing.yml false
savemap 1000 my-map-edited.yml

F5 opens entities, F6 tiles, F7 admin tools. Save under a new name in server-data. For Sandbox play, stop the mapping server and use Server-SS14.ps1 -Map vapor -Play, then launch the client. Both modes bind directly to 127.0.0.1:1212; use one server at a time. Backup-Maps.ps1 archives generated maps, prototypes and saved edits.

Low-power use and testing limits

Close large browser sessions and run one demanding task at a time. The SS14 client uses a 30 FPS cap; keep maps paused while editing and load one at a time. Start with Vapor or Ourang; Hamburg has roughly 37,000 objects. Leave disk room for build caches, updates and working files. No registry tuning, service removal or global security changes are scripted.

Checked: 15 PowerShell scripts parsed with official PowerShell 7.6.6 on Linux; bundle integrity, all four map choices, existing-folder refusal, cached-artifact verification and bad-hash rejection passed. All 19 WinGet package identifiers were found in Microsoft’s manifest repository.

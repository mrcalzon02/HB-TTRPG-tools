Windows alternative: native TGMC/StrongDMM and SS14 setup scripts

Two self-contained setup bundles cover the map editing environments prepared for this laptop. Each includes Tyson, Port Hamburg, SS Ourang Medan and Vapor, with its own source downloads, installer, build helper, editor launcher, local hosting launcher and dated map backup script.

Platform: x86-64 Linux. The prerequisite installers target Linux Mint 21/22 and Ubuntu 22.04/24.04. Use the equivalent packages manually on other distributions. These are local development setups, with portable tool downloads installed inside the folder you choose.

The setup bundles include maps and scripts; the large engine, source and dependency downloads happen during installation. Internet is required for the first installation. The installers refuse an existing destination. Keep your current projects and edited maps separately.

TGMC / SS13: StrongDMM map editing

Installs BYOND 516.1659, StrongDMM 2.18.0.alpha, Node 22.11.0, rust-g 3.11.0, the SpacemanDMM suite 1.11, and a Python map-tool environment. Downloads the pinned main TGMC repository, adds the restored maps and Linux airlock fix, then builds the game and interface.

Download TGMC Setup BundleBundle checksumRead installerFull instructions

Download the bundle into Downloads, open a terminal there, and run:

tar -xzf tgmc-map-dev-linux.tar.gz
cd tgmc-map-dev-linux
bash install-prerequisites.sh
bash setup.sh --check-only
bash setup.sh "$HOME/HB-map-dev/tgmc"

The prerequisite step uses sudo to install system libraries, Geany and the 32-bit compiler/runtime libraries. The remaining setup runs as your normal user. Once installed:

cd "$HOME/HB-map-dev/tgmc"
bash edit.sh tyson
# In another terminal, to host this map:
bash server.sh tyson
# After editing:
bash backup.sh

StrongDMM opens the selected native DMM in the current TGMC project. The host rebuilds and listens on 127.0.0.1:14000. Ctrl+C stops it. Use an existing BYOND player for joining; this Linux bundle does not install the Windows BYOND client or Wine. Map editing and server hosting are included.

SS14: native map editor and Sandbox hosting

Installs portable .NET SDK 10.0.401, clones SS14 at the tested commit with its pinned submodules, adds the four native map ports and breathable editor lobby, and builds both server and client in Tools configuration. Builds run sequentially with limited concurrency for older machines.

tar -xzf ss14-map-dev-linux.tar.gz
cd ss14-map-dev-linux
bash install-prerequisites.sh
bash setup.sh --check-only
bash setup.sh "$HOME/HB-map-dev/ss14"

After installation, start the mapping server and then the client in separate terminals:

cd "$HOME/HB-map-dev/ss14"
bash server.sh
# Second terminal:
cd "$HOME/HB-map-dev/ss14"
bash edit.sh tyson

Enter the printed mapping command in the client console (backtick key). For Tyson:

mapping 1000 Maps/TGMC/Tyson_Station.yml false
savemap 1000 my-map-edited.yml

F5 opens entities, F6 tiles and F7 admin tools. Saves go into the installed folder’s server-data. Save edits under a new name before testing simulation. For a local Sandbox round, stop the mapping server and run bash play.sh tyson, wait for Ready and use bash edit.sh tyson to connect. Both host modes bind to 127.0.0.1:1212; use only one at a time.

bash backup.sh archives generated maps, local prototypes and saved edits. The supplied ports provide independent APC-device power and unrestricted access for editing. Full TGMC missions and power/atmos networks still need adaptation.

Checks, recovery and source versions

Installers verify bundled files and downloaded tools using recorded checksums. Source checkouts are pinned to the versions used by the working environments. System packages and transitive NuGet/npm/Python dependencies are resolved during setup; these bundles are not a complete offline dependency mirror.

Scripts passed shell syntax, bundle integrity, map payload and launcher checks. A fresh end-to-end installation on another computer has not been tested. The existing local installations passed the validation described in the conversion record. The new scripts do not rebuild or replace those existing installations.

If installation stops, keep the failed folder and choose a new destination for retrying. Do not delete it until any edits are backed up. If dependencies are unavailable, check the error and upstream download links. A checksum mismatch stops installation; do not disable verification.

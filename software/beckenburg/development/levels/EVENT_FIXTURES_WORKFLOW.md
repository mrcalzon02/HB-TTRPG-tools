# Ghost event fixtures — production and reproduction

## Archive contents

Six original CC0 model families: rotary telephone with attached handset/coil cord; twin-bell bedside alarm clock; wall-mounted fire bell/strobe; portable wooden radio; cassette boom box; and a small turned-leg support table. Both clean and worn versions are separate GLBs and editable Blender assets. The archive also contains five original synthesized stereo WAV cues and portable activation example data. Filling water reuses the game's existing hollow sink models; its dynamic surface and stream are runtime geometry.

## Repeatable authoring order

1. Finish the room layout, circulation and major furnishings. Identify real supports. Do not float radios above furniture or put wall alarms in openings.
2. Build new original fixtures with `build_event_assets.py`; inspect the actual mesh renders and native metre dimensions. Merge new families into `lived-assets.json` without rebuilding older approved clean files.
3. Age only explicit new IDs with `build_worn_assets.py -- <new IDs>`. Keep clean/worn vertices, normals, UVs, index buffers and pivots identical. `validate_worn_assets.py` verifies the preserved clean hashes and changed diffuse maps.
4. Reserve a valid light-switch operating position before placing an event table. This gate caught a stand blocking the farm dining-room's only switch approach. Place stands with the same wall/circulation/closet/window checks as other furniture; their geometry and collision are authored together.
5. Add a `device` socket on the actual table top. Seed clocks on the free front-right bedside-table corner (local +.22, +.20), opposite the front-left mug and clear of the central lamp. The original back-corner placement passed aim checks but was hidden behind the lamp in actual captures. Derive sink anchors from the existing basin and counter transforms. Find a reachable solid wall face for each room fire alarm, excluding door/window openings and tall obstructions. Keep source front orientation and back mounting depth intact.
6. `HauntedFixtures` owns deterministic fixture IDs, static positions, active state, expiry, water level and revision. Current authored counts: house 19, farm 19, school 17, including 12 individually placed room fire alarms per site. Player E toggles the aimed fixture within reach. Ghost F5 targets an aimed fixture; the host validates room, sightline, range, sequence, energy, cooldown and Frenzy state through the ordinary DISTURB dispatcher.
7. Accepted AI and human DISTURB, MANIFEST and SIGNATURE actions share the same fixture witness path. Rejected actions cannot activate a fixture. Ordinary player switching does not create supernatural evidence. A fixture event lasts at most 200 ticks (20 seconds) unless stopped earlier.
8. Emit phone, alarm-clock, fire-bell, radio and running-water sounds from the actual fixture coordinates through the existing room acoustic projection. Device sounds are original procedural cues. Ghost clients receive a dedicated public fixture-sound frame, preserving the ban on private hunter sound/state feeds.
9. Water rises by 6/1000 of the bounded basin level per 100ms tick while running and drains by 10/1000 per tick after stopping. Render an upward-facing, inset water surface and a narrow stream inside the existing hollow basin. Keep the surface below the rim; it must not cover the whole counter or share a coplanar face with the sink.
10. `FIXTURE` snapshots contain only fixture ID, on/off state, water, expiry and revision. Static coordinates come from the shared authored map. Validate bounds, ignore older revisions, replay on view/reconnect, and keep all frames within the existing protocol limits.
11. Run `HauntedFixturesTest` for all operating positions, wall attachment/openings, actual meshes, AI/human authorization, rejected events, timed activity, filling/draining, replication and distinct audio. `LooseClutterNetworkTest` additionally tests actual ghost activation, replicated state, rejected distant switching and reachable hunter deactivation over sockets. Keep architectural, utility and acoustic compatibility gates enabled.
12. Export original sound WAVs with `EventFixtureAudioExport`. Build the Events Asset Browser library with `build_public_libraries.py -- events`; publish and validate its model/source/preview/audio/data hashes. ZIP entries use fixed timestamps and sorted paths, making unchanged packages reproducible. Verify actual live downloads after deployment.
13. Export `event-fixtures.json` with the exact runtime scene. `build_scene.py` retains each device as an individually editable object with its ID, type, room, activation and water metadata; sink controls are authoring anchors. Capture idle/active devices and filling water through the actual game renderer. Commit each completed gate and verify pushed checkpoints.

## Current implementation and limits

Both fixture and physical-object gates pass, including actual socket requests. These are functional room events with mounted models, state, audio and player controls. The sink has a bounded fill/drain surface; overflow, plumbing simulation and flooding are outside this implementation. Phone receivers, clock bells and cassette lids are not separate pickup parts. Further interactive Windows playthrough and target-resolution performance remain distinct from automated checks and inspection captures. The full installer regression gate has separately documented historical failures.

## Sanity-event object rule and preview lesson

All ghost species may fling loose objects for sanity events. Those flings never acquire a player or arm contact damage; only poltergeist disturbances use targeted, damaging projectiles. Frenzy DREAD also produces harmless scatter. Generic disturbance room damage was removed, so a demon cannot bypass the physical rule. Both controller origins use the same path.

Review actual game-camera images before accepting captures. A view-yaw sign mismatch initially faced away from the devices despite shared-helper tests passing. Fixture aim and loose-object forward vectors now match positive-sine camera X. Capture from a reachable position facing each model's authored front, then inspect the resulting image. Mesh yaw and view yaw have separate conventions.

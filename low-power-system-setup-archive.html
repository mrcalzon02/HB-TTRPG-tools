The original system uses Linux Mint 22.3 x86-64, an i5 M430, about 4 GB of RAM and Radeon HD 5650 graphics. The inventory captures that system. Choose the corresponding target-OS builds on another machine; the full system-package snapshot is a reference, not a universal installer.

Set up another machine in stages

  1. Prepare the system: update your chosen OS and check graphics, audio, networking and file transfer.
  2. Install the essentials: select the reader, media player, file tools and apps you want from the catalog. Use the listed Mint/Ubuntu package names or exact Flatpak identifiers.
  3. Add games and references: install the emulator or engine, then obtain its game data. Copy/download books, music and Kiwix archives while retaining credits and checksums.
  4. Restore projects: clone repositories or restore verified Git bundles into new folders. Locally modified maps and unpublished project files require their separate backups.
  5. Test the intended workflow: launch selected apps and games while online, then test offline use. Export browser-saved campaigns and sheets separately.
  6. Keep a separate backup: copy important working files, installers and map edits to another device.

Keep the workload small

  • Run one demanding program at a time; close large browser sessions before gaming.
  • Use modest OpenTTD worlds and test each 3D game on the target hardware. Smaller DOS, puzzle and homebrew games make useful first checks.
  • Build SS14 sequentially with limited concurrency, use the supplied 30 FPS editor setting, and edit large maps paused.
  • Keep one map loaded. Begin with Vapor or Ourang; Hamburg’s roughly 37,000 objects are most demanding.
  • Treat 45% total drive usage as the trip’s planning target. Avoid duplicate downloads and leave room for updates, caches, swap and working files.

Map editing environments

Open the Development Setup subtab for full instructions. Extract the appropriate bundle, read its README, install prerequisites, run its check-only mode, then install into a new folder. Existing destinations are refused.

The setup bundles target x86-64 Linux. Existing environments passed the documented native checks. Fresh-install scripts were checked for syntax, integrity and launcher behavior; a complete installation on another computer has not been tested. SS14 ports support Sandbox editing and exploration; mission systems and full engineering networks still need adaptation.

Exact recovery and future availability

Source URLs and package versions can age, and some vendor links are mutable. Keep original downloads and verified backups for exact recovery. Missing source provenance is marked in the catalog. Account credentials, browser-local campaigns and unpublished files are recovered separately.

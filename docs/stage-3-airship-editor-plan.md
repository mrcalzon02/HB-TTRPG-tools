# Stage 3 — Airship / Vessel Editor Plan

The next editor in the staged sequence should be the Airship / Vessel Editor.

It should consume outputs from:

- Floating Island / Skyland Editor.
- Settlement / Skyport Editor.

## Reason for Stage 3

Airships are the operating link between islands, settlements, markets, factions, and encounters. Once the system can create a place and a settlement, it needs a way to move people, cargo, conflict, and scarcity between them.

## Inputs to consume

From Floating Island profiles:

- Route access.
- Altitude band.
- Stability / collapse risk.
- Faction pressure.
- Primary resource.
- Threat clock.

From Settlement profiles:

- Trade access.
- Economy base.
- Faction presence.
- Defense posture.
- Civic asset.
- Crisis clock.
- Market pressure.

## Editor controls to add

- Vessel name.
- Hull culture.
- Size class.
- Core type.
- Purpose.
- Legal status.
- Crew quality.
- Crew size.
- Cargo type.
- Armament.
- Condition.
- Maintenance pressure.
- Route license.
- Captain archetype.
- Hidden problem.
- Current mission.

## Derived scores

- Airworthiness.
- Cargo value.
- Combat threat.
- Maintenance risk.
- Legal risk.
- Crew morale.
- Adventure density.

## Outputs

- Vessel summary.
- Crew hooks.
- Cargo hooks.
- Route hooks.
- Faction hooks.
- Maintenance complications.
- Encounter hooks.
- Draft wiki entry.
- Full vessel profile JSON.

## Source-derived anchors

The Kaysender source material supports airships as more than transportation. Ships are homes, trade machines, military platforms, survival infrastructure, smuggling vessels, rescue tools, and faction assets.

The airship editor should therefore treat every vessel as a combination of:

- Hull.
- Core.
- Crew.
- Cargo.
- Route access.
- Maintenance burden.
- Faction/legal status.
- Risk.
- Story pressure.

# Beckenburg Alpha 2.1 — Guest hunter disconnect continuity

When hunter H2 or H3 leaves an active LAN case, the host keeps the match running for the remaining hunters. It retires the seat in LanCase, updates the lobby/team map to show disconnected status, sends PEER|LEFT|SEAT to remove stale network avatars and ceases BODY replication for the vacant seat. Only connected hunters can scan, ward, cleanse or extract, and a vacated seat cannot count as a phantom survivor in ghost-victory checks. A remaining hunter team can still complete the shared three-evidence/anchor ward/cleansing route. Hunter H1's departure still ends the host-owned match. Ghost takeover from Alpha 2.0 remains unchanged. Rejoin/reconnect is **not** implemented; a late join remains rejected.

Tests: LanCaseDepartureTest covers departed-seat legality, idempotence, remaining-hunter rite, and survivor-only defeat. LanGuestDepartureIntegrationTest uses real TCP hunter peers to confirm guest departure, peer removal notice, continuing investigation, completed cleansing, and separately the host departure stop policy. Both commands are included in Linux and Windows Java 17 scripts. Isolated local Java 17-targeted case-rule reproduction passes; clean-source repository build, live four-machine Windows testing and full GUI approval are still required.

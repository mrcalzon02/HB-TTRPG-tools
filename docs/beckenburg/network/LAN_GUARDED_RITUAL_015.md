# Alpha 2.2 — Active ritual defense gate

A player cannot start a three-evidence anchor cleansing and simply walk away for an automatic win. The host advances the rite only while **at least one connected, living hunter** remains in the true anchor room, whether the original initiator or another teammate. The server's current hunter room state and active/health bits are authoritative. An unguarded circle pauses immediately (RITUAL|PAUSED), resumes when defended (RITUAL|RESUMED), and breaks after 20 consecutive unattended 100ms simulation ticks (RITUAL|BROKEN). An abandoned rite never completes silently; its initiator must explicitly cleanse again after returning. The anchor ward remains consumed/prepared, ghost disturbance can continue delaying ritual progress, and the existing 45 defended tick completion threshold remains unchanged. Hunter-only progress and event privacy is maintained.

Regression coverage: LanRitualDefenseTest verifies exactly paused/resumed/abandoned/restarted/completed semantics and snapshot validation; LanRitualDefenseIntegrationTest runs four TCP seats through collected evidence, warding, abandonment, host event publication, explicit restart and case resolution. Both are registered in Java 17 Linux/Windows build scripts. GUI and real multi-PC acceptance remain outstanding; do not interpret source archival as a production release.

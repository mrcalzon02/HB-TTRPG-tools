# Stage 2 Next Improvements

The Settlement / Skyport Editor is now functional as an editor-alpha module. The next improvements should deepen the settlement layer before moving to Stage 3.

## Priority 1 — Population detail

Add derived population outputs:

- Exact population estimate within the selected scale.
- Household count.
- Militia count.
- Dockworker count.
- Farmers / herders / craft workers.
- Specialist NPC count.
- Refugee / transient count.
- Ancestry blend keyed to local culture and island context.

## Priority 2 — Civic layout blocks

Add generated settlement zones:

- Dock / landing zone.
- Market square.
- Cistern or water hall.
- Tavern / neutral ground.
- Grainworks or food-processing site.
- Watchtower / signal tower.
- Militia shelter.
- Guild office.
- Shrine or temple.
- Hidden faction site.

## Priority 3 — Faction logic

Add faction behavior outputs:

- What the faction publicly wants.
- What the faction secretly wants.
- What resource it controls.
- Who opposes it.
- What it offers the players.
- What it will do if ignored.

## Priority 4 — Crisis clock stages

Convert each crisis into staged clocks:

1. Warning signs.
2. Public panic.
3. Institutional failure.
4. Faction exploitation.
5. Irreversible consequence.

## Priority 5 — Save-to-notebook bridge

Add local browser storage for generated profiles so the user can build a campaign notebook before a backend exists.

Potential storage groups:

- Islands.
- Settlements.
- Ships.
- Markets.
- Factions.
- Jobs.
- Encounters.

## Priority 6 — Export to wiki draft

Generated settlements should be promotable into draft wiki entries inside the UI, not just displayed as JSON.

## Priority 7 — Stage 3 handoff

The Airship / Vessel Editor should consume settlement outputs:

- Dock quality.
- Trade access.
- Cargo type.
- Faction presence.
- Defense posture.
- Crisis clock.
- Market pressure.

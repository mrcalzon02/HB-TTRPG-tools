# Reciprocal Charles engram / Agent Skill binding

The registered Foundry skill interface and the canonical `blacklight.charles` personality file are *mutual discovery companions*: every registered skill requires `docs/blacklight/charles-personality-engram.json`; the engram requires `skills/index.json`, an index of **optional** skills. This is not automatic permission to run them.

The index pins a SHA-256 of the exact raw engram bytes. The browser context loader verifies that checksum and the two-way reference before releasing a skill document, and the executable portable loader uses the context loader before loading any runtime scripts. Each registered `SKILL.md` carries required companion metadata and a visible fail-closed instruction. `scripts/validate-agent-skills.mjs` checks both contracts and includes negative tamper cases.

Supported browser hosts cache one verified registry and engram personality object per orchestration context. `HBFoundrySkillContextLoader.clearCache()` invalidates both caches so version changes or integrity checks can be reread. For stronger authenticity, pass SHA-256 values obtained through an **independent** trustworthy channel as `expectedEngramSha256` and `expectedRegistrySha256` to the context loader or executable inspector; both must match raw bytes. The self-test page has optional fields for these pins. `externalTrustPinned` is true only when both pins were supplied and verified.

The offline regression suite covers real WebCrypto hashing, concurrent loads, cache invalidation, corrupted or missing companions, malformed trusted pins, executable inspection gates, ZIP-path traversal, symlinks, and deterministic archives. Run `node scripts/validate-engram-loader.mjs`, `python3 scripts/validate-engram-bundle.py`, and `python3 scripts/validate-agent-skill-projections.py` from repository root. The ZIP verifier additionally accepts `--trusted-registry-sha256` and `--trusted-bundle-sha256` to pin the index and full archive.

A package can be built with `python3 scripts/agent-skill-bundle.py pack --skill foundry-discovery --output dist/skill.zip` and verified with `python3 scripts/agent-skill-bundle.py verify dist/skill.zip --trusted-engram-sha256 <sha256>`. ZIPs contain engram resources, registry and selected skills, plus a locked inventory. Use `--all` for the registered family. Exports are **declarative**: separate runtime requirements remain authoritative.

This arrangement provides mandatory bootstrap and detectable integrity failures **for our compliant clients**. GitHub raw content is public: no instructions or packaging method can force a hostile executor to apply a downloaded engram. Registry and engram supplied by the same mutable origin can be swapped together, so a digest alone cannot authenticate the publisher. Stronger tamper resistance requires externally pinned digests or [independently verified Ed25519 signed releases](ai-access/engram-signed-releases.md), trusted runtimes and scoped tool authorization. Detached release attestations sign exact ZIP, registry and engram checksums; no production signing key is bundled or generated by default. Do not claim that a model's personality overrides the host/system security policy.

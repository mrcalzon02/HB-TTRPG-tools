Desktop prototype 0.1.0

Run the laboratory locally without opening the website.

The desktop edition packages the canonical Binary Cube engine with integrated large-grid and omnidirectional validation, authenticated-envelope system, secure-export layer, expanded grid and mask controls, file transfer controls, canonical JSON key handling, diagnostics, and recovery interface inside an offline application shell. It does not create a separate encryption implementation.

Build and release status

Executable packaging is automated through GitHub Actions.

Pushes affecting the Binary Cube desktop package run its validation suite and attempt native Windows and Linux builds. Tags beginning with binary-cube-v publish successful build artifacts as a GitHub release.

Complete depth-domain verification

Every recommended N-sized key must contain each depth from 0 through N−1 exactly once.

Omnidirectional verification

Every recommended size must pass the algebraic six-direction invariant, and a 256 × 256 key must pass exhaustive projection validation on every face.

Round-trip verification

The build must encrypt and decrypt a binary payload without alteration before packaging continues.

Secure-export verification

The test confirms that external exports omit exposed key identifiers and plaintext-length metadata, then reconstruct correctly with the matching key.

Invalid-key rejection

Duplicated depths, missing depths, malformed permutations, and mismatched keys must be rejected.

Renderer isolation

The Electron renderer runs without Node.js integration and without application network access.

Research classification

This remains experimental tabletop obfuscation.

The downloadable format does not convert the Binary Cube permutation into production cryptography. Do not use it to protect credentials, financial records, private communications, medical information, or other sensitive real-world data.
